REQUEST

请求结构

字段类型必填说明
modelstring是固定 "jev"
stateobject是被判断的内容：message（用户消息）+ 可选 context（业务上下文，如历史工单、账户信息），给得越全判得越准
questionsobject是键为问题 ID（自定义，如 intent、urgent），值为一个题型对象；一次可同时问多个问题

每个题型对象的公共字段：

字段说明
type题型：choice / boolean / score（只有这三种）
instructions给模型的判断指令，写清判断口径（如「判断用户的主要诉求」）
criteria判据，格式随题型不同，见下节
QUESTION TYPES

三种题型

1. choice —— 单选（带完整概率分布）

criteria 是对象：键为选项值（自定义），值为选项含义描述。

"intent": {
  "type": "choice",
  "instructions": "判断用户的主要诉求",
  "criteria": { "refund": "退款问题", "technical": "技术问题", "other": "其他问题" }
}

返回：choice（最高概率选项）+ confidence + probabilities（每个选项的概率）。要自己做阈值分流就直接用 probabilities。

2. boolean —— 真假判断

criteria 可省略（省略时按 instructions 字面判断）。返回只有一个 probability（为真的概率），true/false 阈值由你自定（一般 ≥0.5 视为真）。

"urgent": {
  "type": "boolean",
  "instructions": "是否需要立即处理的高紧急度问题"
}

返回：{"probability": 0.83, "type": "boolean"}

3. score —— 打分

criteria 必须是对象数组，每项一个 {分值: 描述}。返回 probabilities（按档位顺序的分布）+ score（加权期望分）。

"severity": {
  "type": "score",
  "instructions": "用户情绪激动程度打分",
  "criteria": [ {"1": "平静"}, {"3": "不满"}, {"5": "非常愤怒"} ]
}
!score 的换算规则：返回的 probabilities 按档位出现顺序编号（"0"、"1"、"2"…），score = Σ(序号 × 概率)，范围 0 ~ 档位数-1，不使用你在键里写的 1/3/5 数字。要换算成 1–5 分请自行线性映射，例如 3 档时：你的分 = score × 2 + 1。

示例返回：{"probabilities": {"0": 0.01, "1": 0.49, "2": 0.5}, "score": 1.49, "confidence": 0.24, "type": "score"}

分流逻辑示例：intent=refund 且 urgent.probability≥0.8 → 直接进退款快捷通道；severity.score≥1.5 → 附加安抚话术。

import requests

r = requests.post(
    "https://ai.939593.xyz/v1/evaluate",
    headers={"Authorization": "Bearer sk-你的令牌"},
    json={
        "model": "jev",
        "state": {"message": "登录页面一直转圈打不开，急死了"},
        "questions": {
            "intent": {
                "type": "choice",
                "instructions": "判断用户的主要诉求",
                "criteria": {"refund": "退款", "technical": "技术故障", "other": "其他"},
            },
            "urgent": {"type": "boolean", "instructions": "是否高紧急度"},
        },
    },
    timeout=30,
)
r.raise_for_status()
data = r.json()["answers"]

if data["intent"]["choice"] == "technical" and data["urgent"]["probability"] >= 0.5:
    print("→ 转技术支持加急队列")

FAQ

常见问题

它能聊天 / 写代码吗？

不能。它是纯判断模型，只回答你 questions 里定义的问题。拿它当聊天模型用会被 400 拒绝。

一次能问几个问题？

可以多个，三种题型自由组合，价格不变（按请求次数计费，不是按问题数）。建议单次 ≤ 5 个问题，保证判断质量。

结果稳定吗？

同样输入多次调用结果一致（确定性输出），适合做规则化分流；拿不稳的边界场景直接用 probabilities 自己卡阈值。

和让 GPT 输出 JSON 比有什么优势？

不用写提示词、不用解析失败重试、不用怕模型输出幻觉格式：题型即协议，返回必是结构化 JSON，延迟也低得多（秒级）。
